# Private asset evidence storage

AssetPass stores registration evidence in the private Neon Object Storage bucket `asset-evidence`. The API issues short-lived S3-compatible presigned URLs; browser clients never receive storage credentials.

## Configuration

Set the following on the backend only:

- `ASSET_STORAGE_ENDPOINT`: Neon Object Storage endpoint for the production branch.
- `ASSET_STORAGE_REGION`: `eu-central-1`.
- `ASSET_STORAGE_ACCESS_KEY_ID`: access key ID created in the Neon Console for Object Storage.
- `ASSET_STORAGE_SECRET_ACCESS_KEY`: matching secret key. Store as a Vercel secret/environment variable and in a local, untracked `.env`; never commit or send it in chat.
- `ASSET_EVIDENCE_BUCKET`: `asset-evidence`.

All five values are optional as a group for local development. If any are set, all must be set. Evidence upload endpoints return a service-unavailable response until the backend has the credentials. The example endpoint is specific to the current production Neon branch; use a different endpoint for another branch/environment.

## Upload workflow

1. Authenticated client calls `POST /api/v1/assets/evidence/uploads` for an individual, or `POST /api/v1/organizations/:organizationId/assets/evidence/uploads` for an organization. The JSON body contains `fileName`, `contentType`, and `sizeBytes`.
2. API creates a reservation tied to the authenticated user and (when applicable) organization, then returns `uploadId`, a 15-minute presigned PUT URL, and the required `Content-Type` header.
3. Client uploads the file directly to the returned URL with HTTP PUT.
4. Client calls `POST /api/v1/assets/evidence/uploads/:uploadId/complete` or the organization-scoped equivalent. The API verifies the object exists, its exact byte size and content type, and its file signature before marking it uploaded.
5. The registration payload's `evidence` entries now use `{ evidenceType, uploadId }`. The API checks that each upload is complete, belongs to the submitting user and registration context, then attaches it transactionally to the application.
6. Evidence download URLs are short-lived (5 minutes). Individual uploaders can retrieve their own attached evidence. Organization evidence can be retrieved by the uploader or a member with `organization.assets.review`.

## Constraints and security boundaries

- Only PDF, JPEG, PNG and WebP are accepted; maximum file size is 15 MiB.
- Bucket remains private. Object keys are generated by the API and are never accepted from clients.
- Upload and download URLs are bearer credentials; clients must not log or persist them.
- Upload reservations expire after 15 minutes. Uploaded but unattached objects are not yet automatically garbage-collected; an expiry cleanup job is a follow-up.
- File-signature checks detect basic MIME spoofing. Malware scanning, document-content validation, and image metadata scrubbing are not included in this stage.
- Storage credentials must be configured on the backend deployment before enabling the frontend upload workflow. This change does not configure Vercel, create Neon credentials, upload evidence, or deploy the API.
